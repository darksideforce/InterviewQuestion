- `useState` 更新机制
	- react有批处理机制，react会在同一个事件循环内收集多次数据更新合并为一个大的数据更新，并重新渲染，提高渲染性能
	- react有浅比较和渲染跳过的说法，如果新旧值引用不同，则渲染，如果新旧值引用相同则跳过渲染
- `useEffect` 和依赖数组
	- useeffect是用于处理副作用的hook，常见的副作用包括异步获取数据、手动修改dom等
	- 以来数组是useeffect的第二个值，是依赖项，每次渲染react都会使用object.is来判断引用值是否相同
	- 如果不传值则是每次渲染都执行useeffect
	- 空数组则是只在初次渲染时执行一次
	- 传递具体值则是在具体值改变时进行渲染
- Hooks 规则
	- 不能在if或者for循环中调用hooks，因为react的底层虚拟dom是单向链表，hooks放在for循环中会导致顺序错乱
	- hooks只允许在react函数式组件或者自定义hooks中使用
- 介绍一些常用的hooks
	- usememo：缓存高性能消耗的计算结果
	- usecallback：缓存函数引用，也可以用来缓存组件，一般用于配合react.memo
	- useref：获取dom节点以及引用
	- usecontext：跨层级获取数据
	- uselayouteffect：阻塞dom渲染，直到内容执行完毕
	
- usememo和usecallback的区别
	- usememo一般缓存的是函数的计算结果
	- usecallback一般缓存的是函数的引用地址，避免因为传递的是新函数而导致组件重新渲染
- fiber是什么
	- fiber就是react用来计算虚拟dom的一种新架构，它将每个虚拟dom节点构造出一个fiber对象，fiber架构本质上是一个链条， 每个fiber节点都代表一个需要执行的工作单元，分别有三个指针指向父节点、子节点和兄弟节点。每次开始进行渲染时，react就会从头开始遍历fiber链条，创建出一个工作树，所有的更新操作都在新的工作树上执行，并在执行完毕后快速将新的工作树应用在页面上
- `memo`是什么？
	- memo是一个高阶组件（hoc），一般情况下react内部的组件都会跟随父组件的渲染而重新渲染，而memo就是阻止这种行为的，只监听props的修改，如果props没改变则不进行重新渲染
- `key` 和 Diff
	- react的diff算法由于使用的是fiber架构，所以他的diff算法是单向的，从链条一头遍历到另一头
	- vue的算法是双向逼近的算法
	- react每次渲染时都会自顶向下的进行diff比较，而vue可以精确的知道是哪个组件被渲染了，所以react需要使用usememo的方式来进行规避
- 组件重新渲染的原因
	- 自身的state被修改了
	- 父组件被重新渲染了
	- 使用memo的情况下，props被修改了
	- 依赖的context被修改了
- 受控与非受控组件
- 请求竞态处理
	- 通过abortcontroller中断旧的请求
	- 锁定交互，不允许重复发起请求
	- 使用时间戳等方式来判断数据是不是最新的
- React 性能优化
	- 合理使用usememo，降低性能消耗较高的数据
	- 使用react.memo和usecallback，阻止某些组件的重复渲染
	- 状态下放、一些消耗性能较强的组件依赖的属性最好只和自身有关
	- 长列表优化和虚拟列表
	- 代码分割和懒加载，使用react.lazy和suspense，suspense一般是异步组件，用来显示一些加载未显示的东西
- hoc组件是什么
	- 一个接受组件，并返回一个新组件的函数，像react.memo，可以用来塞入打点或者渲染劫持
